# E4 - first- vs second-order (measured)

Same symmetric-Dirichlet scenario (perturbation-recovery), boundary pinned; only the **search-direction slot** varies. Reports iterations AND wall-clock across mesh sizes. `|g|inf` target = 1e-6. Run: `python -m bench.run_e4`.

## Observed

- **Iteration gap is real:** at 10x10, projected Newton converges in 10 iterations vs 52 for L-BFGS and thousands for gradient descent -- second-order needs far fewer *iterations*.
- **But iterations are not wall-clock:** a Newton iteration assembles + solves a Hessian; a first-order iteration is a gradient + line search. Compare the wall-clock column, not the iteration column, across methods -- this is exactly the confound behind published 'N x fewer iterations' claims (E4's point).
- **The iteration-count winner is NOT the wall-clock winner:** at 10x10, L-BFGS took 52 iterations vs Newton's 10 (~5x more) yet finished in 843 ms vs Newton's 955 ms -- L-BFGS wins wall-clock by skipping Hessian assembly. A benchmark that ranked on iterations alone would crown the wrong method; this is why metrics.md pairs the two.
- **Adam plateaus (honesty control):** full-batch Adam ended `maxiter` with |g|inf=3.8e-02 (target 1e-6) -- it normalizes gradient magnitude and ignores curvature, so it stalls above tight tolerance, as predicted (docs/corpus.md World-0). A fixed learning rate is used with NO per-problem tuning.

_Caveat: dense solve, single scenario/seed per size, one Adam lr. The point is the iterations-vs-wall-clock distinction and the Adam plateau, not a tuned horse race._
